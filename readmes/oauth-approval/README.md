# OAuth Approval — The Hideaway

Operational packet for submitting Google OAuth, Naver Login, and Kakao Login
for The Hideaway.

This is not a design note. It is the copy-paste source for provider consoles,
live screenshots, callback URLs, env vars, and pre-submit checks.

## Generate Current Resources

Run this after production has the current code and real provider env vars:

```bash
BASE_URL=https://hideawayseoul.com pnpm oauth:approval:report
```

The report script:

- captures live screenshots into `readmes/oauth-approval/screenshots/*-prod.png`;
- calls Better Auth redirect endpoints with `disableRedirect: true`;
- writes `readmes/oauth-approval/callbacks.md` with the exact outbound
  `redirect_uri` each provider receives;
- stops before any provider login or consent completion.

Use `callbacks.md` as the source of truth for redirect URIs. Native Google and
generic OAuth providers use different Better Auth routes, so do not hand-derive
console callback values from memory.

## Submission Order

1. Run `04-pre-flight.md`.
2. Submit Google first. Basic scopes usually move fastest.
3. Submit Naver and Kakao with the production sign-in screenshot attached.
4. After each approval email, update encrypted production env vars, deploy, and
   smoke-test the provider from a fresh browser.

## Scopes

| Provider | Requested data             | Scope / consent items                          |
| -------- | -------------------------- | ---------------------------------------------- |
| Google   | Email, name, profile image | `openid`, `userinfo.email`, `userinfo.profile` |
| Naver    | Email, name                | Naver console permitted info: email, name      |
| Kakao    | Email, nickname            | `account_email`, `profile_nickname`            |

No contacts, mail, Drive, Calendar, profile-image consent for Naver/Kakao, phone
numbers, birthdays, gender, or address. Any future feature that needs more data
gets a separate provider review.

## Current Code State

- Google remains a native Better Auth social provider.
- Naver and Kakao use Better Auth `genericOAuth`.
- `/sign-in` and `/sign-up` render Google, Naver, Kakao, passkey, and
  email/password options.
- `/privacy` discloses the provider-specific social-login data collected.
- Kakao secrets are required in production: `AUTH_KAKAO_ID` and
  `AUTH_KAKAO_SECRET`.
